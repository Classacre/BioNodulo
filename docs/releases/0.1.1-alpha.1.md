# BioNodulo 0.1.1-alpha.1

This alpha expands descriptor-driven node generation and corrects runtime,
provenance, biological-data handling, and editor issues found during the project
audit. Generated integrations remain experimental and require explicit runtime
configuration and verified environments.

## Generated integrations

The shared CWL reference-engine profile supports shell rendering, directory
artifacts, records, artifact arrays and primitive output values. Primitive
outputs are published as typed JSON files, not native scalar graph edges.
Environment receipts preserve exact upstream requirements and verify installed
files before execution. Missing dependencies and unsupported source features
remain explicit failures in the coverage ledger.

The complete pinned 147-descriptor source cohort currently yields 52 generated
descriptors covering 21 exact bio.tools accessions. All 52 passed CWL syntax
and runtime-readiness checks. Thirteen real app execution cases passed with
independent expected results, exercising 12 descriptors across six accessions.
Forty generated descriptors do not yet have biological execution evidence.

Registry-wide source discovery accounts for all 34,242 records in the verified
snapshot. Official Galaxy parsing identifies 2,289 wrappers with exact xrefs to
421 accessions. Galaxy parsing is discovery evidence; these wrappers are not
yet executable through a shared BioNodulo Galaxy adapter.

## Runtime and editor changes

- Optional parameters remain unset unless supplied or declared by the tool.
- A reusable CWL File Input node carries explicitly declared format URIs and
  secondary files without inferring scientific validity from filenames.
- Output publication, cancellation, binary streams, artifact validation and
  provenance retain stronger evidence and reject invalid states.
- Biological fixes include transcript import paths and normalization handling;
  their scope is defined by the checked fixtures and toolchain tests.
- Version synchronization includes npm and Cargo lockfiles, with Python
  reporting `0.1.1a1` and desktop/web reporting `0.1.1-alpha.1`.

Cloud release synchronization now waits for CI and accepts an immutable prepared
website revision. App, website, catalog and both worker registries are checked
together before website promotion. Production deployment remains a separate
verified operation from publishing source or passing local tests.

These are bounded engineering results. They do not establish universal tool
executability, every option combination, broad scientific validity, or PhD
completion. See `docs/generated-biotools.md` for the execution profile and
reproduction commands.
